# 00. Видение проекта

## 1. Что такое ИГЛА

**ИГЛА** — это локальная инженерная среда, которая решает широкий, но ограниченный круг задач пользователя через обычную просьбу и серию уточнений. По содержанию это **универсальный модельный алгоритм**, в котором ИИ выполняет роль **планировщика/диспетчера**, а реальные действия выполняют отдельные модули, прошедшие регистрацию и политику.

Имя — мнемоническая расшифровка целевых свойств:

```
И — Итеративно
    Не один ответ, а цикл:
    наблюдение → гипотеза → действие → проверка → коррекция.

Г — Генерируемый
    Система сама генерирует планы, проверки, скрипты, тесты,
    патчи и пайплайны под конкретную задачу.

Л — Локальный
    Главный источник истины — реальное состояние машины,
    контейнеров, файлов, логов, проектов, сети.

А — Анализ
    Не «сделал», а построил модель ситуации,
    проверил гипотезы и доказал результат evidence’ом.
```

Короткая формула:

> **ИГЛА — это не LLM-agent. Это проверяющий runtime, в котором LLM является заменяемым планировщиком.**

## 2. Чем ИГЛА не является

ИГЛА — **не**:

- чат-бот, который «отвечает из головы»;
- универсальный алгоритм, способный решить любую задачу мира;
- автономный агент, которому позволено напрямую запускать shell, менять файлы, лезть в сеть, в firewall, в БД и в системные сервисы;
- обёртка вокруг готового агентного фреймворка (LangGraph/AutoGen/Semantic Kernel могут служить ориентиром, но не основой).

Главные антипаттерны, которые система должна делать **невозможными**:

- LLM напрямую вызывает `subprocess` / shell / API без прохождения политики;
- мутация файла, который не был прочитан в текущей задаче;
- следующий шаг, выполненный до получения результата предыдущего;
- повтор того же действия после ошибки без диагностики;
- выкладывание гигантского артефакта (например, Excel 2k×700) в контекст модели целиком;
- запись в память без `source_event` и без проверки на дубликат;
- регистрация AI-сгенерированного модуля без прохождения карантина.

## 3. Контур применимости (где ИГЛА сильна)

Реализуема не «решить любую задачу», а **«решить широкий класс задач внутри заранее заданной среды»**. Целевые домены первой волны:

- **Системная инженерия Linux:** Gentoo USE-флаги, kernel config, dracut/initramfs, SDDM/KWin/Wayland/X11, rollback-планы;
- **Виртуализация:** Quickemu/QEMU/OVMF, диагностика audio/display/network, тестовый boot;
- **Приватность и сеть:** анализ nftables, tun0, killswitch, проверка маршрутов и DNS;
- **ML/LLM-инфраструктура:** CUDA/PyTorch, vLLM, llama.cpp, профили запуска моделей, бенчмарки;
- **Контейнеры:** Docker, NVIDIA Workbench, проверка образов, конфигов, портов;
- **Code-repair:** анализ traceback, патч, повторный запуск тестов, git diff и объяснение;
- **Локальная лаборатория:** A/B-эксперименты с фиксированным prompt’ом, замеры throughput, стабильности, VRAM;
- **Анализ больших табличных артефактов:** Excel/CSV — детерминированный профиль, аномалии, агрегаты, отчёт.

Где ИГЛА **слаба** и сознательно не применяется:

- задачи без проверяемого результата;
- задачи, где ошибка критична, но нет верификатора;
- полностью автономные действия без контроля и без rollback;
- задачи в общедоступной/чужой среде, где нет локального источника истины.

## 4. Главная архитектурная формула

```
LLM proposes. Runtime disposes.
```

ИИ только **предлагает структурированные действия**. Реальный субъект — **IGLA Runtime**, который имеет право сказать:

```
Нет.
Ты не читал файл.
Ты не получил результат предыдущего шага.
Ты не сверился с TODO.
Ты уже получил ошибку — диагностируй, не патчь вслепую.
Ты пытаешься писать в память без дедупликации.
Ты пытаешься засунуть 2k×700 Excel целиком в контекст — запрещено.
```

Эта жёсткость — не «фильтр», а главный архитектурный смысл системы.

## 5. Сквозные принципы

1. **Локальность важнее интернета.** Приоритет источников: локальное наблюдение → локальная проверка → официальная документация → веб → модельная догадка.
2. **Evidence-first.** Никакое утверждение не попадает в финальный отчёт и память без ссылки на evidence (вывод команды, прочитанный файл, прошлый кейс, выдержка из документации).
3. **Обратимость по умолчанию.** Любая мутация — `backup → action → verification → commit | rollback`.
4. **Модули знают только протокол.** Между собой модули общаются исключительно через типизированные артефакты, никогда напрямую.
5. **Состояние важнее промпта.** Что «нельзя дальше», что «нужно сначала диагностировать», что «контекст переполнен» — решает state machine, а не уговоры в промпте.
6. **Память отделена от лога.** Лог — append-only факты времени. Память — продукт дедупликации, проверки и архивации.
7. **Никакой магии в эффектах.** Любое изменение мира идёт через kernel effect tools, не через произвольный код модуля.
8. **Стабильный протокол ≠ стабильные модули.** Реализации, версии и наборы tools могут меняться постоянно; envelope’ы — нет.

## 6. Что значит «универсальный»

«Универсальный алгоритм» здесь — не один большой кусок кода. Это **универсальный оркестратор внутри ограниченной среды**, который умеет:

- понять кривой человеческий запрос;
- собрать `TaskSpec`;
- выбрать нужные capabilities из реестра;
- собрать план в виде DAG из шагов;
- прогнать его через политику;
- выполнить шаги в sandbox;
- собрать evidence и проверить успех;
- обновить память;
- объяснить пользователю, что сделано и почему.

Список tools при этом может расти: новые домены, новые модули, новые верификаторы. Но универсальность даёт не их количество, а **общий протокол**, через который они подключаются.

## 7. Целевая роль для пользователя

Пользователь общается с ИГЛОЙ как с локальным SRE/DevOps/ML-инженером, который:

- не выдумывает причины «из головы»;
- сначала смотрит реальную систему;
- задаёт уточняющие вопросы там, где задача неоднозначна;
- предупреждает о рисках перед каждым необратимым действием;
- предоставляет отчёт с доказательствами после выполнения;
- сохраняет рецепт решения в память, чтобы в следующий раз сделать быстрее.

ИГЛА не «играет в эксперта». Она **становится** проверяющей средой, в которой даже не самая умная модель ведёт себя как инженер, потому что иначе runtime её просто не пропустит.
