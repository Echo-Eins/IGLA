# Документация ИГЛА

> ИГЛА — **Итеративно-Генерируемый Локальный Анализ.**
>
> Не чат-бот. Не «универсальный ИИ». Это **локальный проверяющий runtime**, в котором LLM выступает заменяемым планировщиком, а реальные действия выполняются строго через политики, sandbox и верификаторы.

Этот каталог содержит первый вариант проектной документации, выведенной из расширенного черновика (`README.md` в корне репозитория). Цель — зафиксировать видение, требования, архитектуру и протоколы до того, как написана первая строчка ядра.

## Принципы, которые проходят сквозь всю документацию

1. **LLM proposes. Runtime disposes.** Модель не имеет прямого доступа к инструментам, файлам, shell, сети, памяти. Она только формирует структурированные предложения.
2. **Не «модель умная», а «среда жёсткая».** Безопасность и качество держатся на протоколе, политиках и state machine, а не на интеллекте конкретной модели.
3. **Прочитал → доказал → сделал → проверил → сохранил.** Любое действие требует evidence; любой mutation — backup, verifier и план отката.
4. **Стабильным должен быть протокол, а не реализация.** Заморожены envelope’ы (ToolInvocation, ToolResult, ArtifactDescriptor, EventRecord, PolicyDecision, MemoryRecord). Реализация модулей и LLM — заменяемы.
5. **Локальность — главный источник истины.** Сначала смотрим на реальную систему пользователя; интернет/документация — второй приоритет; «модельная догадка» — последний.

## Статус

Это черновик `v0.1`. Документы описывают целевое состояние системы и порядок её сборки, но **не** обязывают реализовывать всё сразу. Реализация ведётся по плану из [11-roadmap.md](11-roadmap.md).
